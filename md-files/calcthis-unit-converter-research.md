# Unit Converter — research + decisions (2026-10-29, DEPLOYED v241, commit 7ce0c67)

**SEO structure (user approved 2026-10-29):** hub `/unit-converter/` (head >10K Hard; every variant <100) + one page per category + (LATER) one page per high-demand pair (cm to inches, kg to lbs, celsius to fahrenheit, px to rem, cups to grams, mb to gb…) — the user will send Ahrefs screenshots for the pair terms; add them to a PAIRS list in the generator then. Phase 1 pages: `/length-converter/ /weight-converter/ /volume-converter/ /temperature-converter/ /area-converter/ /speed-converter/ /data-storage-converter/ /cooking-converter/ /px-to-rem-converter/`.

**Competitors opened live:** unitconverters.net (≈90 converters, Express box + "Common conversions" pair grid, no visuals), calculator.net (6-tab converter + essay); convertunits.com 403.

**Differentiators built:** every unit in the family at once (table), swap, formula line, copy; visual: length = dual cm/inch ruler (0–32 cm), temperature = thermometer scale with marker, px/rem = live text sample; functional: inches as tape-measure fractions (nearest 1/16), pounds as lb + oz, data: decimal (KB) vs binary (KiB) explained, cooking = cups↔grams for 50 ingredients (US/UK/AU cup) + oven °C/°F/fan/gas mark, px/rem with editable root + parent font size + viewport (vw/vh). Not built (said plainly): visuals for weight, volume, area, speed, data; pair pages.

**Code:** `CalcThis.unitEngine` (pure, `UNIT-ENGINE:START/END` in assets/app.js) + `CalcThis.initUnitConverter` (ids `un*`, body `p-loan p-unit data-cat="<cat>"`); CSS `.p-unit` at the end of style.css; generator `md-files/gen-unit-pages.js` (all SEO numbers from the engine; registers sitemap, build.js PAGES, llms.txt, header/footer partials (UNITNAV/UNITFOOT markers), homepage tab `grp-units` + hasPart). Factors are exact international definitions (BIPM SI brochure, NIST SP 811, IEC 80000-13). Cooking densities are typical values (~±5%), copied from the Recipe Converter table; oven: gas mark nearest standard setting (225–475 °F, tolerance ±12.5 °F), fan = °C − 20.

**Rules in the UI:** negative allowed only for temperature/length/speed; below absolute zero rejected; gas marks only ¼ ½ 1–9; oven 0–1000; vw/vh need viewport values (Go advanced); category dropdown navigates and carries the typed value 15 s (`sessionStorage unForm`, test hook `window.__unNoNav`).

**QA run:** engine matrix 130,794 checks (every unit pair × 16 values: round trips, identity, linearity, formatting, every ingredient × cup standard, parse, known values) = 0 failures; UI: 80 random unit/value combos per page × 10 pages vs engine, 18 garbage inputs, 11 odd-but-valid inputs, 300 random control steps with invariants per page (no NaN, big = sticky bar, no overflow, no dup ids), oven-mode fuzz; px/rem base/parent/viewport cases; 375px + desktop screenshots; hub→category navigation with value; homepage tab. Found+fixed: thermometer label overflow for huge values, dp formatting ≥1e21, oven rounding, ruler label overlap, text wording. NOT verified: real phone, real Chrome (Copy), print.
